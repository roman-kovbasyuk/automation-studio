# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Vibe coders who need practical, reusable interface building blocks and clear examples while assembling web products.

## Product Purpose

The design system makes it faster to build consistent interfaces by providing reusable components, interaction patterns, and documentation that can be copied into working projects. Success means a developer can find an element, understand its behavior, copy its identifier or code, and use it correctly with minimal friction.

## Positioning

The system combines a broad component library with documentation designed around direct interaction: previews, element identifiers, copy actions, and executable usage examples.

## Operating Context

Users browse a categorized documentation site, inspect live component previews, review source examples, and copy identifiers or code into their own applications.

## Capabilities and Constraints

- React 19 and TypeScript implementation.
- Shared atomic design-system layers: atoms, components, UI blocks, and documentation screens.
- Components expose interaction behavior through reusable APIs and shared tokens.
- Documentation should support click-to-copy element IDs and code, live interaction, previews, and clear variation coverage.
- Existing component APIs, accessibility behavior, and the AlignUI structure for documentation grouping and page layout should be preserved.
- The repository is private and uses local Vite development and production builds.

## Brand Commitments

The product name is Brutalist Design System. Documentation may acknowledge AlignUI as structural inspiration while keeping implementation and code original.

## Evidence on Hand

The repository contains the current React/TypeScript component library, token definitions, atomic boundary checks, documentation pages, and runnable Vite demos. No external customer or usage evidence has been provided.

## Product Principles

- Make reusable interface behavior easy to discover.
- Show working examples before asking users to read implementation details.
- Keep copied output precise and immediately useful.
- Preserve semantic structure and accessible interaction.
- Prefer shared primitives over one-off screen markup.

## Accessibility & Inclusion

Preserve semantic HTML, keyboard access, visible focus states, accessible names, and the existing automated accessibility-oriented component tests.
